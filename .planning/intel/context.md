# Context

## AI Voice Chatbot Implementation Plan
- source: docs/superpowers/plans/2026-05-16-ai-voice-chatbot.md
- Goal: Build a Mac Electron desktop app that listens continuously with VAD, transcribes speech via STT, sends to a configurable LLM, and speaks the response back via TTS — with barge-in support to interrupt playback.
- Architecture: Pure Electron app. React renderer owns VAD (via `@ricky0123/vad-react`), streams audio to main process over IPC. Main process owns provider adapters (STT/LLM/TTS), conversation state, and settings. All three provider types implement TypeScript interfaces, making them hot-swappable via a settings panel.
- Tech stack: Electron 28, electron-vite 2, React 18, TypeScript 5, `@ricky0123/vad-react`, `@anthropic-ai/sdk`, `openai`, `ollama`, Vitest, `@testing-library/react`.
- Structure: 14 tasks, TDD-driven (failing test → implement → passing test → commit) — Task 1 Project Scaffolding, Task 2 Shared Types and Provider Interfaces, Task 3 Conversation Manager, Task 4 LLM Providers (Claude/OpenAI/Ollama), Task 5 STT Provider (Whisper API + macOS stub), Task 6 TTS Providers (macOS say + OpenAI TTS), Task 7 Pipeline and Provider Factories, Task 8 Preload Script and IPC Handlers, Task 9 Main Process Entry Point, Task 10 WAV Encoder Utility, Task 11 useVAD Hook, Task 12 React Components (ChatHistory/StatusBar/SettingsPanel), Task 13 App.tsx Root Component Wiring, Task 14 End-to-End Verification.
- Parallelization notes: Tasks 4/5/6 independent after Task 3; Tasks 10/11/12 independent after Task 2; Tasks 7→8→9 sequential; Task 13 depends on Tasks 11 and 12.
- Key file map: `src/main/{index.ts,ipc.ts,settings.ts,conversation.ts,pipeline.ts,providers/{stt,llm,tts}/*}`, `src/preload/index.ts`, `src/renderer/{App.tsx,main.tsx,types.ts,env.d.ts,hooks/useVAD.ts,components/{ChatHistory,StatusBar,SettingsPanel}.tsx,utils/wav.ts}`.
- Settings model: `AppSettings { llm: {provider: claude|openai|ollama, model, apiKey, baseUrl?}, stt: {provider: whisper-api|macos|whisper-local, apiKey}, tts: {provider: macos-say|openai-tts|elevenlabs, apiKey, voice?}, conversationWindowSize }`. Defaults: llm=claude (model claude-sonnet-4-6), stt=whisper-api, tts=macos-say, conversationWindowSize=10.
- Barge-in behavior: `useVAD` raises `positiveSpeechThreshold` to 0.90 while TTS is playing (vs 0.50 idle) to avoid the AI's own voice triggering barge-in; on speech detected while playing, renderer stops TTS and cancels the in-flight LLM call before transcribing the new utterance.

## VAD "Mic error" Debug Handoff
- source: docs/vad-mic-error-debug-handoff.md
- Status: RESOLVED (2026-05-30) — app renders and VAD reaches "Listening" in dev.
- Root cause 1 — CSP `worker-src` blocked blob worker: Chromium/Electron does not honor `worker-src` set via an HTML `<meta>` CSP tag, only via HTTP response headers. Fix: set CSP via `session.webRequest.onHeadersReceived` in `src/main/index.ts`; dev config additionally allows `'unsafe-inline'` for Vite's React Fast Refresh preamble (production stays strict `script-src 'self' 'wasm-unsafe-eval'`). The redundant CSP `<meta>` tag was removed from `src/renderer/index.html`.
- Root cause 2 — ONNX Runtime WASM module path resolution wrong: `@ricky0123/vad-web` is CommonJS and does `require("onnxruntime-web/wasm")` at load, which dynamically imports `ort-wasm-simd-threaded.mjs` via a relative URL that Vite resolves incorrectly to the `.vite/deps/` cache folder instead of `node_modules/onnxruntime-web/dist/`. Fix: moved `onnxruntime-web` from `optimizeDeps.exclude` to `include` in `electron.vite.config.ts` (excluding it caused an unsupported dynamic-require shim crash instead), and added dev-only middleware (`serveOrtWorkerAssets`, `apply: 'serve'`) to serve `.mjs` files from `public/` as raw static JS (Vite's dev server 500s on `public/` files requested through the module pipeline; `.wasm`/`.onnx` load fine via `fetch` unaided).
- Known follow-up (not blocking dev): the dev middleware only applies in `serve` mode. For a packaged production build (`file://` protocol), `wasmPaths = '/'` resolves to filesystem root and will need a relative/base-aware path — not yet verified against `npm run build`.
- Files touched: `src/main/index.ts` (CSP via `session.webRequest.onHeadersReceived`), `electron.vite.config.ts` (`optimizeDeps.include` + dev middleware), `src/renderer/hooks/useVAD.ts` (`baseAssetPath: '/'`, `onnxWASMBasePath: '/'`; `ortConfig` setting `wasm.wasmPaths` recommended), `src/renderer/index.html` (CSP `<meta>` tag removed).
- Approaches tried that did NOT fully resolve the issue (don't repeat): `optimizeDeps.exclude` alone; `baseAssetPath`/`onnxWASMBasePath` alone without `ortConfig`; clearing `node_modules/.vite` cache; CSP `<meta>` tag updates for `worker-src`.
- Debug workflow: `npm run dev` starts Electron with CDP on port 9222; `agent-browser --cdp 9222 console` used to inspect VAD errors.
